- **Security hardening** following an external security review. Same Hermes UI as 0.2.2 (158fd638, tested
  against Hermes 0.21.5); only the Android bridge changed.
- **Cleartext now needs consent on local networks.** `http://` is still accepted silently for Tailscale
  (`100.64.0.0/10`, `*.ts.net`) and loopback. For LAN addresses (`10/8`, `172.16/12`, `192.168/16`,
  `169.254/16`, `*.local`, single-label names) the connect screen now explains that the password and session
  token would travel unencrypted on that network, and the Connect button stays disabled until you tick
  "I understand, connect anyway over this network". The choice is remembered only for that exact server URL;
  a different address asks again, and sessions that are already signed in keep working. Any other `http://`
  host is still refused.
- **Link titles only contact public web hosts.** The title preview for links in chat no longer follows
  `file:`, loopback, Tailscale, LAN or IPv6-literal targets, checks every redirect (at most 3) and reads at
  most 64 KB of `text/html`. A public DNS name that resolves to a private address (DNS rebinding) cannot be
  detected from the WebView; this is documented in the README.
- **Media is checked before it is downloaded.** The app asks the server for the file size first and refuses
  anything over 64 MB without transferring it (the size is still checked after download as a backstop).
  Finished audio/video Blob URLs are now kept in a small LRU cache (128 MB, 24 entries) and revoked when
  evicted, unless a player is still using them.
- Docs: the README compatibility table now reads `0.2.x`, and the Security section describes the new
  transport and link-title rules.
